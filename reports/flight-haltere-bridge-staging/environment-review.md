# Independent staged-environment review

Reviewed `reports/flight-haltere-environment-staging/staged/web/training/environment.js` against the frozen bridge API. This is a read-only source review; no native fly or neural model was run for it. File hashes are recorded in `environment-review.json`.

No blocking input-routing or timing defect was found in the reviewed version.

- **Root frame:** the sample uses `body.data.qvel.slice(3,6)` directly. The native XML's first body is the thorax with the free joint (`models/flybody-mujoco.xml:204`). For a free joint, MuJoCo defines the rotational velocity in the local body frame, matching the virtual geometry's root-local coordinates. No extra rotation should be added. [Official MuJoCo floating-object conventions](https://mujoco.readthedocs.io/en/stable/overview.html#floating-objects).
- **Phase/frequency:** the sample reads `body.wings.phase` and `body.wings.frequencyHz`, which the actual wing controller updates. It does not substitute the 236 Hz normalization reference for the current oscillator frequency. The controller advances phase to the current body time after its control interval.
- **Timing:** `parameterValues` enforces 0.5 ms neural ticks and 2 ms body blocks. The environment samples offsets 0, 0.5, 1, and 1.5 ms, then performs one sequence call before the existing 2 ms `world.tick`. This is the declared held-body approximation: root Omega and muscle power are held; virtual phase advances analytically. It does not claim four newly observed body states.
- **Power:** `fly.feedback.halterePower` is copied from the corresponding body's normalized asynchronous-haltere forces by `copyPose`. The present IO maps left power to index 97021/root 720575941546998972 and right power to index 118683/root 720575941572052381. Missing versus present-zero side values remain distinguishable in bridge diagnostics; no other organ's power is supplied as a fallback.
- **Allocation and identity:** the four dense current vectors are allocated once per episode and reused with `.set(input)`. `writeInto` computes a small 328-value result and overwrites only its checked indices. Prepared IDs are fetched once when either tegula or haltere feedback needs them, with length/SHA verification. The haltere factory checks those exact IDs against all current haltere annotations.
- **Default/control paths:** absent flags retain the existing `brain.step`; `neuralInputSequence:true` without haltere feedback sends constant copies as a separate control. Haltere feedback necessarily enables the per-tick sequence path.

Two nonblocking audit/performance notes:

1. The old `encoder.sample.body.rates` entries still describe the legacy rate proxy, and the old rate-to-current mapper is still called for the haltere rows before their values are overwritten. Those intermediate values do **not** reach the neural solver in the haltere branch. Analyses must use `haltereCurrent` (pA, `replacesLegacyHaltereRateCurrent:true`) for the active haltere input. Skipping the unused haltere calibration/conversions would remove wasted work, but is not necessary for correct delivered currents.
2. `encoder.sample.haltereCurrent` retains the final 1.5 ms sample of each block, not all four samples. `onPhysicsStep` runs after the subsequent physical advance, so its current native Omega differs in timestamp from this held-input record. `sourceBodyTimeSeconds`, `sourcePhaseRadians`, `mostRecentInputOffsetSeconds`, and the bridge's recorded `omegaRootRadS` identify the actual input. The current record should not be interpreted as a post-physics measurement or a full four-sample trace.

The environment integration test should assert the exact four offsets, reuse of the same vector identities, non-haltere equality in every vector, direct zero current with missing/zero side power, and absence of `stepSequence` on the default path. The bridge's 12 pure-module tests already pass; environment execution and full-fly validation remain the parent's work.
