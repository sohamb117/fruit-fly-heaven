The installed MuJoCo TypeScript declaration exposes `mj_rnePostConstraint`, `cfrc_int`, `cfrc_ext`, `xaxis` and `xanchor`. Existing application/scaffold code does not provide a verified total wing-base reaction-wrench helper. No native function or simulation was executed for this inspection.

MuJoCo documents `cfrc_int` as the parent/body interaction wrench in a tree-COM-based frame, stored torque before force; the orientation is world-aligned. `mj_rnePostConstraint` must be called when the relevant acceleration/force sensors have not already requested it. The API therefore offers a possible wrench route, but returning its six entries directly as wing-frame forces would be wrong. [Official API documentation](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html#mj-rnepostconstraint).

The inspected upstream implementation assembles body external wrenches from applied Cartesian forces, contacts and selected equality constraints, then subtracts these from inertial wrenches and accumulates children. It does not explicitly subtract `qfrc_fluid` or general joint-space applied/passive forces in that routine. This raises a concrete accounting question for interpreting it as a complete wing-base reaction under aerodynamic loading; it is not a verified defect in the pinned WASM binary. Validate known-load balance and action/reaction before adopting that interpretation. [Upstream implementation](https://github.com/google-deepmind/mujoco/blob/main/src/engine/engine_core_smooth.c#L2235).

The simpler proposed quantity `qfrc_fluid[wing DOFs]` is explicitly an aerodynamic generalized-load projection. With three coincident hinge anchors and nonsingular world-axis matrix A (one hinge axis per row), solving `A M = tau_fluid` recovers the associated Cartesian aerodynamic moment at that anchor. Check singular values, anchor coincidence and timestamp/cache alignment. It does not recover the complete six-component wrench, inertial/actuator reaction or tegula strain. The current rigid model has no deformable tegula, so any load-to-receptor mapping remains a stated proxy rather than measured sensillum mechanics.
